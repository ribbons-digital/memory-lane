## Currentness tie-break dogfood

A temporary isolated project fixture used two approved project checkpoints with identical high lexical overlap for the query `what is the current Memory Lane release status?`:

- `stale-release`: older `project_checkpoint`, `updatedAt` 2026-06-29.
- `current-release`: newer `project_checkpoint`, `updatedAt` 2026-06-30.

Command shape:

```bash
MEMORY_LANE_FILE="$tmp/memory.jsonl" \
MEMORY_LANE_CONFIG="$tmp/config.json" \
MEMORY_LANE_EMBEDDINGS="$tmp/embeddings.jsonl" \
memory-lane recall "what is the current Memory Lane release status?" --project "$proj" --json
```

Result:

- `semantic.enabled` was `false` and `semantic.used` was `false`, proving lexical fallback behavior.
- The first result was `current-release`.
- The second result was `stale-release`.

This confirms the installed `v0.2.41` artifact prefers the newer checkpoint when explicit current release-status recall has an exact lexical-score tie between checkpoint records.

## Interpretation

The release shipped the PR #75 equality-only currentness tie-break without broadening retrieval scope.
Lexical score remains primary.
The release does not filter stale records out of top-k, add threshold recency boosts, enable embeddings, add RRF/reranking, add public eval commands, or change lifecycle budgets.

The remaining baseline precision findings are lower-ranked distractors and should not be expanded into another retrieval-ranking slice without fresh eval evidence or dogfood pressure.

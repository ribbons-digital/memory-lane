## Release scope

`v0.2.44` should ship:

- bounded legacy home-stored project memory diagnostics in `memory-lane status`, `memory-lane doctor`, and MCP `memory_status`;
- `memory-lane migrate project-local --dry-run` as a preview-only command;
- explicit `MEMORY_LANE_*` single-store mode reporting legacy diagnostics as not applicable;
- documentation for the read-only legacy diagnostics path;
- reliability and maintainability hardening from the Fable 5 waves.

This release must not introduce confirmed migration, silent record movement, deletion, approval, rejection, consolidation, retrieval/ranking rewrites, lifecycle prompt warnings, dedicated MCP tools, or MCP warning surfaces beyond explicit `memory_status` diagnostics.

## Installed-artifact dogfood plan

After the release workflow publishes `v0.2.44`, run:

```sh
memory-lane --smoke-test
memory-lane upgrade --yes
memory-lane --smoke-test
```

Then verify Slice 2a from the installed artifact with an isolated fixture:

1. Create a temporary project with a stable `.memory-lane-scope`.
2. Create a home-store legacy project-scoped approved memory for that scope.
3. Run `memory-lane status --json --project <fixture>` and confirm `legacyProjectMemories.totalLegacyCandidateCount` is `1` without creating project-local storage.
4. Run `memory-lane doctor --json --project <fixture>` and confirm the same bounded diagnostics are present.
5. Run MCP `memory_status` with `projectPath` set to the fixture and confirm it inherits the same bounded diagnostics without memory bodies.
6. Run `memory-lane migrate project-local --dry-run --json --project <fixture>` and confirm it reports the candidate and does not mutate files.
7. Run `memory-lane migrate project-local --project <fixture>` without `--dry-run` and confirm it refuses to mutate.

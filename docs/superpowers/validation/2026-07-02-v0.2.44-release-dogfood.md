## Slice 2a installed-artifact dogfood

Created an isolated temporary fixture with:

- a temporary `HOME` containing a home-side `.memory-lane/memory.jsonl`;
- a project directory with `.memory-lane-scope` set to `dogfood-scope-v0.2.44`;
- one approved home-stored project memory matching that project scope;
- no project-local `.memory-lane/memory.jsonl` file.

Then ran the installed binary commands:

```sh
HOME="$fixture/home" memory-lane status --json --project "$fixture/project"
HOME="$fixture/home" memory-lane doctor --json --project "$fixture/project"
HOME="$fixture/home" memory-lane migrate project-local --dry-run --json --project "$fixture/project"
HOME="$fixture/home" memory-lane migrate project-local --project "$fixture/project"
```

Also ran installed `memory-lane mcp` through the MCP stdio client and called `memory_status` with `projectPath` set to an isolated fixture.

Results:

- `status --json` reported `legacyProjectMemories.status: "ok"` and `totalLegacyCandidateCount: 1`.
- `doctor --json` reported the same bounded legacy diagnostics.
- MCP `memory_status` reported `legacyProjectMemories.status: "ok"` and `totalLegacyCandidateCount: 1` for the fixture `projectPath`.
- MCP `memory_status` used the same bounded sample-preview shape as CLI diagnostics.
- `migrate project-local --dry-run --json` reported the same candidate under `legacyProjectMemories`.
- `migrate project-local` without `--dry-run` exited `1` with the expected refusal: `Mutating project-local migration is not implemented in this release. Run memory-lane migrate project-local --dry-run to preview legacy records.`
- The fixture still had no project-local `.memory-lane/memory.jsonl` file after all CLI commands.
